# RamBo

A Windows RAM and process cleaner. Finds duplicate process trees, hung windows,
zombies, suspended and orphaned processes, trims working sets, and manages
startup entries.

![RamBo](icon_preview.png)

## Download

**[Download the latest release](../../releases/latest/download/RamBo-Setup.exe)**

Run `RamBo-Setup.exe`. It installs for the current user only
(`%LOCALAPPDATA%\Programs\RamBo`), so there is no admin prompt, and it adds a
Start Menu shortcut and an entry in Apps & Features.

> The installer is unsigned, so Windows SmartScreen shows *"Windows protected
> your PC"*. Click **More info** → **Run anyway**.

## What it does

**Processes tab**

| Column | Meaning |
| --- | --- |
| `Dupe · Main` | Root process of a multi-instance app (Chrome, Electron, …) |
| `Dupe · Child` | A child of that root |
| `Not Responding` | Window is hung (`IsHungAppWindow`) |
| `Zombie` | Process is dead but not reaped |
| `Suspended` | Process is stopped |
| `Orphan` | Parent is gone and the process is 12h+ old |

- **TRIM RAM** calls `SetProcessWorkingSetSizeEx` across all processes, asking
  Windows to page out idle working sets. It does not free leaked memory.
- **KILL CHILDREN** terminates a duplicate group's children and leaves the root
  running — usually what you want for a misbehaving browser.
- Right-click a row for *Open file location*, *Copy PID*, *Copy row*, *Kill*.
  `Ctrl+A` selects all, `Ctrl+C` copies as TSV, `Delete` kills.
- **ADMIN** appears when not elevated. Terminating system-owned processes and
  editing protected startup entries needs it.

**Startup tab** — lists `HKCU` / `HKLM` run keys, scheduled tasks, and the user
and common Startup folders, and enables or disables them.

## Building from source

Requires Python 3.13+ (the app is built and tested against 3.14).

```
pip install -r requirements.txt
build.bat
```

`build.bat` builds, packages, and publishes a GitHub release in one pass:

| Command | Result |
| --- | --- |
| `build.bat` | Build → installer → GitHub release |
| `build.bat --no-upload` | Build only |

The installer step compiles `installer.iss` with Inno Setup 6, which must be
installed once:

```
winget install JRSoftware.InnoSetup
```

Publishing needs the GitHub CLI, authenticated once:

```
winget install GitHub.cli
gh auth login
```

Bump `APP_VERSION` in `main.pyw` to cut a new release; the tag and title follow
from it. `icon.ico` and `logo.png` are generated by `make_icon.py`.

## Updating

Installed builds update themselves. On launch they check GitHub Releases, and
if a newer version exists they download `RamBo-Setup.exe`, run it silently and
exit; the installer replaces the files and relaunches RamBo. There is no
prompt — progress is reported in the status bar, and the install waits for a
running scan, trim or kill animation to finish so the app never disappears
mid-action.

An **UPDATE** button appears only as a fallback, if the automatic download or
install fails; it offers the same update with a confirmation dialog.

The check is stdlib-only, runs on a background thread, and fails silently when
offline. It is disabled entirely when running from source, so a dev tree is
never overwritten by a published build. To turn it off in an installed build,
set `"update_check": false` in `%LOCALAPPDATA%\RamBo\settings.json`.
